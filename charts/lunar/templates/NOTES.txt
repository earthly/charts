Deprecated — connection options written as a string:
{{- range $stringOptions }}

  Helm logs "cannot overwrite table with non table" for these. That line is
  expected and your value IS applied — it appears only because the chart's
  default is a map now. Strings are accepted for the rest of chart 3.x and
  removed in 4.0.0.

  As a map, the chart renders each consumer's syntax for you:

    hub:
      db:
        connectionOptions:
          sslmode: require
{{- if $multiOption }}

  More urgently, these carry more than one option, which is not merely
  deprecated but wrong today:
{{- range $multiOption }}
  {{ . }}
{{- end }}

  A string reaches all five consumers unchanged. The hub, the migrate Job and
  the operator read libpq keyword/value pairs, separated by spaces; the SQL
  API and the Grafana datasource receive the query of a postgres:// URL,
  separated by "&". One option is valid both ways. A second is valid in
  exactly one, so the rest are configured with a value they cannot parse —
  silently.
